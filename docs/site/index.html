Sit at any of your machines and open a terminal on any other.

jaunt toluene puts you in a tmux session on the machine called toluene, over a direct encrypted link when one can be made and through a relay you host when it cannot. One static binary, no root, no accounts, no third-party service.

The live mesh

Type jaunt with no arguments and you see every machine you have linked, drawn from the one you sit at. A solid green line is a direct path between the two machines. A dotted amber line goes through the relay. A greyed-out machine is offline.

Each link carries its latency and a sparkline of the last minute, and the log underneath says what happened: a laptop roamed to a new network, a relayed path upgraded to a direct one. Arrows to choose a machine, Enter to hop, q to quit.

Linking two machines

jaunt link on one machine shows a short code like 4127-tremor-kudos. Type it on the other with jaunt join. Both screens then show the same small picture and the same three words. If they match, press y on both; if not, press n.

Underneath is SPAKE2, a password-authenticated key exchange with the code as the password. Someone in the middle gets exactly one guess per code, 1 in 60 million; a wrong guess burns the code, and codes expire after 5 minutes. The picture is the second, human check.

The roster, and laptops that stay reachable

jaunt ls prints every machine: direct, relayed or offline, its latency, its sessions, and what its lid would do.

A laptop that sleeps cannot be hopped into. jaunt host on keeps it awake with the lid closed only while it is plugged in and not too hot; on battery, when hot, or when jaunt cannot tell, it sleeps as usual, so it will not cook in a bag. No real laptop has run this yet.

If a laptop is lost, jaunt unlink toluene --kill-sessions from any other machine cuts it off at once on every machine that is online, and lists any machine that has not heard yet.

How it works

 your terminal                                               the other machine
 jaunt toluene ── daemon ════ QUIC + TLS 1.3 ════ daemon ── tmux session
                     │   direct when possible        │
                     └──── else through the relay ───┘

Each machine runs a small background service holding its own key.

Machines only accept keys on the shared member list, checked during the encrypted handshake.

The networking and encryption come from the iroh library, not from jaunt; jaunt adds the linking ritual, the member list and revocation, the hop commands, the mesh view and the lid guard.

Sessions live in tmux on the far machine, which is why they survive disconnects.

Before you trust it

Keep your existing SSH path for now. jaunt is new, has had no outside security review, and has only been tested in a simulated network lab. Leave the way you reach your machines today (for example SSH through a Cloudflare tunnel) in place until jaunt has proven itself on your real machines.

  • Tested only in simulation. A Docker lab with three machines behind simulated home routers passes 250 end-to-end checks. No real laptop, lid, relay server, home network or Mac has run it. What was tested
  • No outside audit. Not of jaunt, not of the iroh library under it, and not of the SPAKE2 crate the pairing uses. A stolen, unlocked laptop is a full member until you revoke it. Security model
  • Unsigned releases. The installer checks the binary against a checksum that comes from the same place as the binary. That catches a broken download, not a malicious release.
  • Speed. In the lab a keystroke took 81 ms on jaunt's direct path against 121 to 139 ms for SSH through a relay host, with 20 ms of simulated delay per router. The gain is the direct path; through the relay jaunt is no faster than SSH. Numbers and method
  • Choices made for you, and the ones that are yours: where the relay runs, and when to retire the path you use today. Decisions

When Tailscale is the better choice. Tailscale's free plan plus tmux (and mosh, for typing over bad links) gives the same speed win in about fifteen minutes, on a WireGuard data plane that is formally verified and maintained by a company whose job it is, with phone, Windows and macOS clients and a better rate of direct paths. Choose it if you want an audited, mature tool now, need phones or other operating systems, or do not mind root and an account. jaunt is for when you want no root, no system VPN device, no account and no company that can add machines to your network. Install

On each machine, as the user who will use jaunt (the script refuses to run as root):

curl -fsSL https://raw.githubusercontent.com/ZahakJ/jaunt/main/install.sh | sh

Options pass through after sh -s --, for example … | sh -s -- --name benzene. Then look before setting anything up:

jaunt demo

It puts one static binary in ~/.local/bin and nothing else unless you ask, and says whether that directory is on your PATH. No root. Linux x86_64 is the only platform with a release binary; everything else builds from source with cargo build --release.

Releases are not signed. The checksum comes from the same place as the binary, so it catches a broken download, not a malicious release.

The relay. Your machines need one relay, a small meeting point you host that introduces them and carries traffic when no direct path exists. It sees only encrypted data and can never add a machine. The cheapest option is free: your desktop, behind a Cloudflare tunnel you already have. The relay chapter compares the options.
